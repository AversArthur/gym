# Gym Log: личный дневник тренировок

План для Claude Code. Читай целиком перед началом работы. Делай по фазам, после каждой фазы останавливайся, показывай результат и жди подтверждения.

## Контекст

Я тренируюсь 3 раза в неделю по программе A·B·C (набор мышечной массы). Нужно веб-приложение, которое:
- открывается на телефоне в зале и показывает программу дня с анимациями упражнений;
- сохраняет каждый подход (вес, повторения) в базу данных на моём VPS;
- показывает, что я делал в прошлый раз, и подсказывает, когда прибавлять вес;
- даёт смотреть историю и графики прогресса за недели и месяцы.

Сначала пользователь один (я). Позже (фаза 10) появятся другие пользователи по приглашению: у каждого свои тренировки, программа, свои упражнения и прогресс. Открытой регистрации, соцфункций и SaaS-биллинга не будет. Простота важнее «правильной» архитектуры, но колонку `user_id` закладываем в схему сразу (фаза 2), чтобы потом не мигрировать живые данные.

**Референс:** `reference/trenirovki-prototype.html` — рабочий прототип (сейчас лежит в корне, в фазе 1 перенести в `reference/`). Из него берём:
- **движок анимаций** (функции `solve`, `solveFront`, `body`, `lerp`, пропсы `plate`, `db`, `grip`, `cable`, `rope`, `handle`, цикл `requestAnimationFrame`, поддержка `prefers-reduced-motion`);
- **объект `EX`**: все 21 упражнение с названием, позами A/B, снарядом (`st`), пропсами и подсказками по технике;
- **объект `PLAN`**: дни, порядок, подходы, повторения, суперсеты, отдых;
- **визуальный стиль**: цвета дней (A красный, B синий, C зелёный), шрифты, светлая и тёмная темы.

Анимации переносим как есть (SVG + JS), не заменяем на GIF и картинки.

## Стек

- **TypeScript** везде
- **Backend:** Node.js 22 + Fastify
- **БД:** SQLite (файл на диске) через Drizzle ORM + better-sqlite3. Для одного пользователя этого достаточно, бэкап — один файл
- **Frontend:** Vite + React (или Preact). Mobile-first, PWA
- **Графики:** uPlot или Chart.js
- **Деплой:** Docker Compose: контейнер `app` за уже существующим на VPS nginx + certbot (HTTPS по Let's Encrypt). Caddy не нужен, см. «Деплой»
- Монорепо: `/server`, `/web`, `/shared` (общие типы и данные упражнений)

Если считаешь, что что-то из этого заметно хуже альтернативы, скажи до начала работы, а не меняй молча.

## Модель данных

```
users                          -- с фазы 2 одна строка (я, role='admin'), с фазы 10 — несколько
  id, username UNIQUE, password_hash, display_name, role ('admin'|'user'),
  created_at, disabled bool

sessions                       -- с фазы 9
  id (случайный токен, храним хеш), user_id, created_at, expires_at, user_agent

exercises
  id            text PK        -- slug: 'squat', 'bench', 'rdl' (как ключи в EX)
  owner_id      int null       -- null = общее упражнение из сида, иначе личное упражнение юзера
  name_ru       text
  name_en       text
  equipment     text           -- barbell | dumbbell | cable | machine | smith | bodyweight
  muscle        text
  cues          json           -- массив строк
  anim_key      text           -- ключ анимации в движке (обычно = id)
  weight_mode   text           -- 'total' | 'plates_only' | 'per_dumbbell' | 'stack' | 'assisted'
  archived      bool

programs
  id, user_id, name, is_active, created_at   -- активная программа у каждого юзера своя

program_days
  id, program_id, code ('A'|'B'|'C'), title, subtitle, position

program_items
  id, day_id, exercise_id, position,
  sets int, rep_min int, rep_max int (оба null = «макс»),
  unit text                  -- 'reps' | 'sec' (планка: rep_min/rep_max в секундах)
  superset_group int null,   -- одинаковое число = суперсет
  rest_sec int,              -- отдых ПОСЛЕ этого упражнения; у первого в суперсете 0
  weight_step real           -- 2.5 для верха, 5 для ног

workouts
  id, user_id, program_day_id (set null при удалении дня), day_code ('A'|'B'|'C' на момент тренировки),
  client_id UNIQUE (офлайн-создание), started_at, finished_at, notes, bodyweight_kg real null

workout_sets
  id, workout_id, exercise_id, set_index,
  weight real, reps int, duration_sec int null,
  rir int null,              -- повторов в запасе (необязательно)
  completed_at
  client_id text UNIQUE      -- uuid с клиента, для идемпотентной офлайн-синхронизации

bodyweight_log
  id, user_id, date, kg
```

`workout_sets` принадлежит юзеру через `workout_id`. Для пользовательских упражнений `id` генерируется (`u<user_id>_<slug>`), чтобы не пересекаться с сидом.

## Экраны

### 1. Сегодня (главный экран)
- Сверху предложение следующего дня по ротации (после A → B → C → A) и кнопки A / B / C, чтобы выбрать другой.
- Кнопка «Начать тренировку» создаёт `workout`.
- Если тренировка не завершена, при открытии приложения сразу возвращаемся в неё.

### 2. Тренировка (самый важный экран, им пользуются в зале одной рукой)
- Карточки упражнений в порядке программы, суперсеты сгруппированы (как в прототипе, полоса слева).
- В каждой карточке: анимация, подходы × повторения, подсказки по технике (сворачиваемые).
- **Строка «В прошлый раз»:** вес × повторения по подходам из последней тренировки с этим упражнением, например `40 кг · 10 / 9 / 8 / 8`.
- **Строки подходов:** поле веса и поле повторений, предзаполненные значениями прошлого раза. Крупные кнопки −/+ (шаг веса из `weight_step`, повторы ±1). Кнопка ✓ сохраняет подход.
- **Ручной ввод веса:** поле веса всегда можно тапнуть и ввести любое число с клавиатуры (цифровая клавиатура, `inputmode="decimal"`, принимает и `,` и `.`), например 37,5 или 13, если такой вес не попадает в шаг −/+. Кнопки −/+ дальше шагают от введённого значения.
- **Подсказка прогрессии:** если в прошлый раз во всех подходах достигнут `rep_max`, показать «Пора прибавить: +2,5 кг» и предзаполнить новый вес.
- **Таймер отдыха** стартует автоматически после ✓ (длительность из `rest_sec`, в суперсете — после второго упражнения пары). Вибрация (`navigator.vibrate`) и звук по окончании, если доступны. Таймер виден поверх экрана.
- Можно добавить лишний подход, удалить подход, пропустить упражнение, оставить заметку.
- Кнопка «Завершить»: итог (длительность, общий тоннаж, рекорды).
- Экран не должен гаснуть во время тренировки: Wake Lock API, если доступен.

### 3. История
- Список тренировок по датам (день, длительность, тоннаж). Тап → подробности.
- Можно редактировать и удалять подходы задним числом.

### 4. Прогресс
- Выбор упражнения → график: максимальный вес в рабочем подходе, расчётный 1ПМ (формула Эпли: `w × (1 + reps/30)`), тоннаж за тренировку.
- Переключатель периода: 4 недели / 3 месяца / всё время.
- Блок «Месяц назад vs сейчас» по каждому базовому упражнению.
- График веса тела из `bodyweight_log` (ввод веса на главном экране, необязательно).

### 5. Программа
- Просмотр и редактирование дней: порядок, подходы, повторения, отдых, суперсеты, замена упражнения.
- Изменения не трогают историю (история ссылается на `exercise_id`, а не на `program_item`).

### 6. Экспорт
- Скачать все данные в JSON и CSV.
- Кнопка «Скопировать отчёт за неделю» — текст вида
  `03.10 A: Смит 40×10,9,8,8; Жим 60×10,10,9,8; ...`
  чтобы я мог вставить его в чат с тренером.

## Офлайн (обязательно)

В зале часто нет связи. Приложение должно работать без сети:
- Service worker кэширует оболочку приложения и программу.
- Каждый подход сначала пишется в IndexedDB с `client_id` (uuid), затем отправляется на сервер. Без сети операции копятся в очереди и уходят при появлении связи.
- Сервер делает upsert по `client_id`, повторная отправка не создаёт дублей.
- В интерфейсе маленький индикатор: «сохранено» / «ждёт синхронизации (3)».

## Безопасность

Приложение висит в интернете, поэтому:
- Вход по паролю. Хеш пароля (argon2) в переменной окружения `APP_PASSWORD_HASH`, скрипт `npm run hash-password` для генерации.
- Сессия в httpOnly secure cookie на 90 дней, чтобы не вводить пароль в зале.
- Rate limit на `/api/login` (например, 5 попыток в минуту).
- Все `/api/*`, кроме login, требуют сессию.
- Секреты только в `.env`, `.env` в `.gitignore`, в репозитории `.env.example`.

## Деплой на VPS (на поддомен)

Цель: приложение открывается по ссылке вида `https://gym.<мой-домен>` с телефона и компа, ставится на домашний экран как PWA. Деплоим только после того, как всё проверено и утверждено локально.

- `docker-compose.yml`: `app` (Node, отдаёт API и собранный фронт) + `caddy` (reverse proxy, HTTPS).
- SQLite-файл в volume `./data/gym.db`.
- `Caddyfile` с доменом из переменной окружения (`APP_DOMAIN=gym.example.com`).
- Если на VPS уже работает nginx/Caddy/Traefik на 80/443 — свой `caddy` не поднимаем, а добавляем в существующий прокси блок для поддомена → `app:3000` (или `127.0.0.1:3000`). Отдельный файл `docker-compose.proxyless.yml` для этого случая.
- `deploy/README.md` с пошаговой инструкцией для чистой Ubuntu 24.04: установка Docker, настройка firewall (ufw: 22, 80, 443), DNS-запись, `.env`, `docker compose up -d`, обновление (`git pull && docker compose up -d --build`).
- Для PWA нужен HTTPS, поэтому нужен домен (подойдёт и поддомен).

**Шаги деплоя:**
1. Собрать и прогнать продовый образ локально (`docker compose -f docker-compose.yml up --build` с `APP_DOMAIN=localhost`) — убедиться, что всё работает так же, как в dev.
2. Создать DNS-запись: `A gym.<домен> → IP VPS` (и `AAAA`, если есть IPv6). Проверить `dig gym.<домен>`.
3. На VPS: проверить, что занято на 80/443 (`ss -tlnp`), выбрать вариант (свой Caddy или существующий прокси).
4. Установить Docker, настроить ufw, создать пользователя для деплоя (не root), доступ по SSH-ключу.
5. Положить код на VPS: приватный git-репозиторий (GitHub/GitLab) + `git clone`, либо `rsync`.
6. Создать `.env` на сервере (пароль/секрет сессий, домен). `.env` создаю я сам, Claude его не читает.
7. `docker compose up -d --build`, проверить HTTPS-сертификат, логин, запись подхода, офлайн-режим с телефона.
8. Включить бэкапы (cron), проверить восстановление из бэкапа.
9. Скрипт `deploy/update.sh`: `git pull && docker compose up -d --build && docker image prune -f`.

**Фактическое состояние VPS (проверено 2026-10-04):** `78.47.246.235`, Ubuntu 24.04, 3.7 ГБ RAM, 20 ГБ свободно. На 80/443 уже работает **хостовый nginx + certbot** с поддоменами `*.arturavers.com` (status, pdf, zipline, …). Порты 3000, 3001, 8080 заняты. ufw выключен.
→ Решение: **свой Caddy не поднимаем.** Контейнер `app` слушает `127.0.0.1:3100`, в nginx добавляется `/etc/nginx/sites-available/gym.arturavers.com` по образцу `status.arturavers.com` + `certbot --nginx -d gym.arturavers.com`. Поддомен: `gym.arturavers.com` (A-запись → 78.47.246.235). Включение ufw — отдельно и осторожно, чтобы не отрезать SSH и другие сервисы.

7. **Редактор программы.**
8. **Офлайн и PWA.** Service worker, IndexedDB-очередь, индикатор синхронизации, установка на домашний экран. Проверка: в режиме «авиарежим» можно провести тренировку целиком, после включения сети всё на сервере без дублей.
9. **Авторизация и деплой.** Пароль, сессии, rate limit, Caddy, бэкапы, `deploy/README.md`, выкладка на поддомен по шагам из раздела «Деплой». Проверка: открываю `https://gym.<домен>` с телефона, логинюсь, провожу тренировку.

## Фаза 10: несколько пользователей

Цель: я могу добавить друга/знакомого, он заходит по своей ссылке и паролю, ведёт свои тренировки, создаёт свои упражнения и программу, видит только свой прогресс. Модель — приглашения от админа (меня), без открытой регистрации.

**Шаги:**

1. **Авторизация по юзерам.** Перейти с `APP_PASSWORD_HASH` в env на таблицу `users` (argon2-хеш в БД). Логин = username + пароль. Сессии в таблице `sessions` (можно отозвать). Скрипт `npm run create-admin` для первого входа; мой существующий аккаунт и данные остаются как есть (у них уже есть `user_id = 1`).
2. **Изоляция данных.** Каждый запрос получает `userId` из сессии; все запросы к `programs`, `workouts`, `workout_sets`, `bodyweight_log`, личным `exercises` фильтруются по нему. Чужой `id` в URL → 404. Сделать это одним слоем (хелперы/репозитории), а не вручную в каждом роуте. Тесты: юзер B не может прочитать, изменить или удалить данные юзера A ни через один эндпоинт, включая `/api/sync` и экспорт.
3. **Приглашения.** Админ-экран «Пользователи»: создать приглашение → одноразовая ссылка `/invite/<token>` (срок 7 дней), по ней человек задаёт имя и пароль. Список юзеров, отключить юзера (`disabled`), сбросить пароль (новая ссылка). Таблица `invites (token_hash, created_by, expires_at, used_at)`.
4. **Стартовая программа для нового юзера.** При регистрации по приглашению: выбрать «скопировать шаблон A·B·C» или «пустая программа». Программа копируется в его `programs`, дальше он её меняет сам, мою не трогает.
5. **Свои упражнения.** Экран «Упражнения → Добавить»: название, снаряд, мышечная группа, подсказки по технике, `weight_mode`, шаг веса. Анимация: выбрать из существующих 21 (`anim_key`, например своё «жим на скамье узким хватом» → анимация `bench`) или без анимации (иконка снаряда). Свои упражнения видны только владельцу; общие (из сида) видны всем и только читаются (редактирует админ).
6. **Прогресс и история по юзеру.** Все экраны (История, Прогресс, Экспорт, отчёт за неделю) работают в контексте текущего юзера. Сравнения между юзерами и общих лент не делаем.
7. **Офлайн-очередь с учётом юзера.** IndexedDB-очередь привязана к `userId`; при выходе/смене аккаунта неотправленные операции не уходят от чужого имени (предупреждение «есть несинхронизированные подходы»). Сервер проверяет, что `workout_id` в синке принадлежит юзеру сессии.
8. **Безопасность.** Rate limit на логин по IP и по username, CSRF-защита для cookie-сессий (SameSite=Lax + проверка Origin), профиль: смена своего пароля, «выйти со всех устройств».
9. **Бэкапы и экспорт.** Бэкап остаётся одним файлом на всех. Экспорт — только своих данных. Удаление юзера админом удаляет его данные (с подтверждением).
10. **Проверка.** Два аккаунта на двух устройствах параллельно проводят тренировки, офлайн и онлайн; данные не смешиваются, у каждого свой прогресс и свои упражнения.

## Чего НЕ делать

- Не добавлять открытую регистрацию и соцфункции (ленты, лайки, сравнение с другими). Новые пользователи — только по приглашению админа (фаза 10).
- Не тянуть тяжёлые UI-киты и CSS-фреймворки ради пары кнопок.
- Не заменять SVG-анимации картинками или сторонними GIF.
- Не хардкодить программу в коде фронтенда (только сид).
- Не коммитить `.env`, базу и бэкапы.
